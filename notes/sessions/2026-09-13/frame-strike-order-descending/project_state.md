# Project State — frame-strike-order-descending

本会话的"为什么"。改动本身见 `handoff.md`。

## 问题本质：同一件事有两套反向语义

改动前，纵轴方向在两侧是**相反**的：

```
帧 strikes      [7640, 7645, ... , 7755]     索引 0 = 最低价
屏幕自上而下     7755 → 7640                  索引 0 在最下方
```

两边各自都"对"，但**读代码的人要在脑子里翻转一次**：帧的第一个元素对应屏幕的
最后一行。KAI 的诉求是"避免歧义" —— 让数组的阅读顺序与屏幕的视觉顺序同向。

## 关键陷阱：这两处**必须成对改**，改一处就出错

ECharts 的 category 轴默认把**索引 0 画在最下方**。于是：

| 帧顺序 | `yAxis.inverse` | 屏幕自上而下 | 判定 |
|---|---|---|---|
| 升序（改动前） | 无 | 7755 → 7640 | 视觉对，但语义反向 |
| **降序（本次）** | **true** | **7755 → 7640** | ✓ 视觉不变 + 语义同向 |
| 降序（只改帧） | 无 | 7640 → 7755 | ✗ **翻转，低价在上** |

所以"把帧改成降序"这个动作**单独做是错的** —— 它会翻转屏幕，正好与 KAI 要的
"行权价高的在上"相反。必须同时给 `yAxis` 加 `inverse: true`。这一条已实测
（见 `handoff.md` 的三组合读数），也已写进项目 `MEMORY.md` 防重踩。

## 为什么排序落在 `build()`，而不是别处

三个候选位置，只有一个正确：

| | 做法 | 判定 |
|---|---|---|
| **A（采用）** | `HeatmapEngine.build()` 遍历 rows 时 `sorted(..., reverse=True)` | ✓ **产出点**：`strikes`/`rights`/`values` 由同一循环产出，顺序只定一次 |
| B | 在 L4 `HeatmapSerializer.encode()` 里 `reversed()` | ✗ 矩阵对象升序、帧降序 ⇒ 又制造一层反向语义 |
| C | 前端 `heatmap.js` 里 `.reverse()` | ✗ 把 L3 的不变量复制到前端，与「前端是空壳」冲突 |

选 A 的理由是**职责归属**：帧的顺序是对外契约，而 `build()` 是这份契约的唯一
产出者。放在这里，L4 与前端都**不需要**知道顺序 —— 谁再排一次，就是第二处真相。

## 为什么显式 `sorted()` 而不是 `reversed(rows)`

`StrikeWindow.rows()` 恰好返回升序，是它的实现细节，不是本模块可以依赖的契约。
用 `reversed(rows)` 就等于把帧的行序建立在一个**跨模块的巧合**上 —— 上游哪天
改了顺序，帧会静默跟着变，而没有任何检查会红。显式 `sorted(..., reverse=True)`
把这条不变量收回到产出点。判据与上一会话一致：

> **不变量要么由产出点保证并有回归，要么就是隐式假设。**

## 刻意**不做**的事

- **不给前端加门禁。** 只加了 `inverse` 这一个渲染参数。KAI 2026-09-13 裁定
  「前端是空壳，后端报多少就渲染多少」；给空壳加"必须降序"的校验，等于把 L3
  的不变量复制到前端。方向参数是渲染职责，不变量是后端职责，两者不混。
- **不改冷数据 `dump_bucket()` 的升序。** 它是**内部恢复产物**（`session.db`），
  与帧是两个层：帧面向前端，冷数据面向 `recover()`。上一个会话刚给它加了
  `sorted()` + 键序回归，本轮不推翻。代价是"冷数据升序、帧降序"并存 ——
  已知并记录在 `OPEN-RISKS`，是否统一交 KAI 定。
- **不动 `recover()` / `load_snapshot()`。** 读侧不重排，理由同上一会话：
  读侧重排 = 第二处真相。
- **不保留兼容分支。** 不写"如果帧是升序也照画"的兜底 —— 帧顺序是契约。

## 同族事实（下次动这块时一起想）

纵轴方向这条不变量现在有**三个承载点**，且必须同时一致：
`features/heatmap_engine.py::build()`（数据顺序）、`web/heatmap.js::yAxis.inverse`
（渲染方向）、`tools/smoke_test.py`（回归）。**只改前两个而忘了回归**，就又回到
"无回归的隐式假设"。同类"跨文件必须同时改"的地方还有：限速桶容量与 IBKR 配额
（自检 [11] 跨 `ibkr.json` + `subscription.json` 核对，已机械守住）。
