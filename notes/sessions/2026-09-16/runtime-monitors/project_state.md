# Project State: runtime-monitors

## 为什么需要"两个"探针

**后端全绿不等于前端不抖。** 帧里的 `heatmap` 到屏幕上那张图，中间要过
`matrix_codec.decode` → `sliceZones` → `aggregate` → `clipTail` → `applyViewport`
五道变换。任何一道把已定稿的列改掉，**帧本身仍然是干净的**。
所以 `tmp/monitor_backend.py` 验"发出去的数据"，`tmp/monitor_frontend.js`
用真实浏览器读"页面上真正画出来的矩阵"——两者不可互相替代。

## 三个"看起来通过、其实没看"的陷阱（本轮全部实测踩到并修复）

### 1. 帧里根本没有 `values` 字段

`heatmap` 块线上发的是 `bm16`（`bm` 位图 base64 + `i16` 定标整数 base64 + `scale`），
**没有** `values`。第一版探针直接读 `block["values"]` → 永远 `None` →
指纹恒 0、改写恒 0，打印出来却是"0 处改写 ✓"。
修法：自己写 `decode_matrix()` 逐位还原，并**校验 `k == len(nums) == filled`**，
任一对不上就返回 `None`，由调用方记为 FAIL（而不是当成"没数据"跳过）。

闸门证据：把解码器改回 `return None` 后，探针输出
「逐格指纹 0 个 … FAIL：帧 #17775 的矩阵解不开 —— 逐格判据在这帧上是空转的」。
**它没有把"什么都没看"报成 PASS。**

### 2. 指纹不能用行号当键

热力图纵轴是"以现价为中心的 ±12 档"窗口。现价一移动，窗口整体平移，
**行号集体换身份**。按 `(row, col)` 存指纹会拿两行不同行权价的数据互比。
实测：第 0 行在两个身份之间来回切换（`(7665, C)` 128 帧 / `(7670, C)` 98 帧），
后果是 **50827 条假改写**，而数据流一个字节都没被改。

修法：键 = `(行权价, 方向, 列)`。
反证：换成按行权价后，300s / 665 帧 → **0 改写**。
探针把 `row_identity_swaps` 也打印出来，作为"为什么不能用行号"的活证据。

### 3. 列身份不能用轴标签，也不能用行长

- `view.labels` 是被 `clipTail` 裁过尾、`sliceZones` 跳过空档之后的**那一段**，
  不是从第 0 列起的完整轴 ⇒ `labels[c]` 与"第 c 列数据"不对应。
- 矩阵只从**右端**追加，左端会被裁掉，所以稳定身份是"距右端偏移"
  （`cols - 1 - c`）。
- **但还要记住这个偏移是在哪个 `cols` 下取的**。最后一版假报的根因是：
  我用 `view.values[r]` 的实际行长当 `cols`，而它与页面自报的 `view.cols`
  会差一；取样途中行长涨 1，同一次采样算出的偏移就与上一帧错开一列。
  修法：`cols` 一律取 `sample.cols`，且**只在 `cols` 与建指纹时一致时才比数值**，
  不一致就重建（记为 `rescale`，不是改写）。

## 一个真的契约边界（不是缺陷）

`heatmap.cols != session.bucket_index` 偶发差 1（529 帧里 1 次）。
成因：`frame.session` 与 `frame.heatmap` 来自**两次独立读钟**
（前者走 `MarketState.session_block()` → `clock.describe()`，
后者走 `FeatureEngine.compute()` 内部的 `bucket_index_of_ts(now)`）。
两次读钟之间跨过 30s 边界，就得到 `cols = current-1`。

判它是采样假象的三条实测依据：
1. 桶内秒 = **29.998**（距边界 2 毫秒）；
2. 差值**恒为 1、方向恒为 `cols < bucket_index`**（矩阵落后，从不超前）；
3. 前一帧正常 ⇒ 出现即恢复，不是永久偏移。

**允许差 1 且落后；差 >1 或超前一律 FAIL**（超前 = 把没走满的桶也发了）。

## 拒绝的选项

- **不给前端加曲面残差副图**：KAI 驳回「前端会变得很挤」。
  残差只留在帧数据里，前端从未消费 —— 是独立未开工任务，不在本轮。
- **不在启动时静默跳过前端验证**：Playwright 自带浏览器没下载时，
  第一版想直接跳过。已改为**扫缓存找一个真实存在的 Chromium 用
  `executablePath` 指定**；一个都找不到就**明确报 FAIL**。
  理由：跳过会让"前端未验"看起来像"前端通过"。

## 非空转验证的边界（诚实记录）

- **已验证会被抓住**：后端解码器改坏（M1）→ FAIL；
  前端指纹键改回行号（M1）→ 67870 处假改写 → FAIL。
- **未验证（本轮未激活）**：后端 T3 挂钟对齐判据恒真、
  前端 T4 把"不一致"故意不标记。原因：本轮观测期内**确实不存在**
  未对齐的列、也**确实不存在**不一致的格，所以变异体没被执行到。
  要验它们，得先构造一个"真违例"的输入。**本轮未构造，故标未验证，不冒充通过。**
