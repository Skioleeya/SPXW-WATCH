## 问题本质：系统里"行权价的顺序"只有一个承载点，而它是历史的函数

`HeatmapEngine._buckets` 是 `dict[float, dict[int, float]]`，键的插入序 =
**该行权价第一次被观测到的时刻**，不是排序结果。链条上没有任何一处排序：

```
StrikeWindow.rows()  →  _build_cells  →  cells_for  →  observe()  →  dump_bucket()
   sorted() 升序          保序            保序        setdefault      插入序
                                                      建键
```

前四步都只是**不重排**，只有第一步真的排了序。于是"冷数据是升序"是
**上游不变量的副作用**，而不是持久化层的不变量 —— 这正是它无回归却看起来
理所当然的原因。

### 非单调怎么产生（机制，不是猜测）

- 现价上移 → 更高的档位进入窗口 → 追加到 `_buckets` 末尾，**仍单调**；
- 现价回落到会话初低点之下 → 更低的档位进入窗口 → **追加到末尾**，**破坏单调**。

`_prune()` 不救：它按桶序号删**每个档位内部**的过期桶，从不删 `_buckets` 的键
—— 键集合只增不减，所以"更低的新键"永远排在旧键之后。

实测（±12 档，真 `StrikeWindow` + 真 `HeatmapEngine`，spot 7700→7820→7600）
第 7 桶即出现 `[... 7735, 7740, 7625, 7630, 7635, 7640]`。
**0DTE 日内一次百点往返就够触发**，不是构造出来的极端场景。

### 为什么"隐式顺序"是真问题

`json.dumps` / `json.loads` / JS 对象都**保留键序**。所以 `ivs_json` 的键序
不是"未定义的实现细节"，而是**会被读到的事实**：直接查 `session.db` 的人
（或未来写的回放/分析脚本）若默认"键序即升序"，就会把行号错配到别的行权价上
—— 静默出错值，没有任何检查会红。

## 三个候选方案与取舍

| | 做法 | 判定 |
|---|---|---|
| **A（采用）** | `dump_bucket()` 输出前按行权价排序 | 最小、且落在**唯一产出点** |
| B | 不排序，只在 docstring 声明"不保证升序" | **不够** —— 声明只是把坑写清楚，读者仍要自己防；而且"冷数据是升序"这件事从此没人能依赖 |
| C | schema 加 `strikes` 列 / `schema_version` | **过重** —— 冷数据是恢复用的中间产物，不是对外数据集；加列等于给它升格 |

选 A 的理由不是"顺手"，而是**职责归属**：`dump_bucket()` 是 `ivs_json` 的
唯一产出者，产物应当与内部字典的历史无关。排序放在这里，读侧（`recover()` /
`load_snapshot()`）就**不需要**再排 —— 两处都排才是第二份真相。

代价可忽略：每次 `_persist_current_bucket`（`compute()` 后调用）对几十个键排
一次序，微秒级。

## 刻意**不做**的事

- **不在读侧重排。** 写侧已保证，读侧重排 = 同一条不变量有两处实现，改一处
  忘一处时不会报错。
- **不给前端加门禁。** KAI 2026-09-13 裁定「前端是空壳，后端报是多少就渲染
  多少」。本次实测确认前端**逐字照抄帧的 `strikes`**（`heatmap.js:93` 只有
  `strikes.map(String)`，`yAxis` 无 `inverse`）—— 这恰恰**支持**空壳定位：
  顺序错了是后端的事，前端不修、也不该被要求修。给空壳加"必须升序"的门禁
  等于把 L3 的不变量复制到前端。
- **不写迁移/重排旧库。** 现有 `data/session.db` 40 桶实测全升序，
  没有脏数据要修；为一个"可达但未触发"的问题写迁移是多余的。

## 同族事实（下次动这块时一起想）

`StrikeWindow.rows()` 返回升序是**上游保证**，冷数据"看起来升序"依赖它。
同类"依赖跨模块巧合"的地方还有：`heatmap_rows_each_side ≤ num_strikes_each_side`
（已由自检 [6] 跨文件守住，见 skill `spxw-live-verify`）。判据一致：
**不变量要么由产出点保证并有回归，要么就是隐式假设。**
