# Project State — skew-period-consistency

本文件只放**推理**：设计取舍、被否掉的方案、坑。改动清单与命令证据在
`handoff.md`，此处不重复。

## 1. 为什么"Skew 跟着周期聚合"选 A 而不是 B

KAI 的目标定义（原文）：

> 我在前端设置了多周期的切换标签。目标：iv 热力图和 SKEW 图必须按周期标签保持
> 一致性：比如我选 30 秒周期，IV 热力图和 skew 就是 30 秒周期。

两条候选路径：

* **A. Skew 跟着一起聚合**（KAI 选定）—— 两块图共用一套列网格，Skew 取组内末值。
* **B. Skew 保持 30 秒基线，只让热力图换周期** —— 两块图横轴不同粒度。

B 被否掉的理由不是"不一致"这种审美问题，而是**盯盘时的可读性**：同一屏幕上下两块
图，横坐标必须指向同一时刻，否则"热力图这里亮了一片、Skew 此刻什么样"这个最基本
的对照动作做不了。B 下用户得自己在脑子里换算两套刻度。

## 2. Skew 为什么取组内**末值**而不是求和

热力图存的是相邻基线桶之间的 IV 差，把一组并成一个更粗的桶时组内求和 —— 望远镜
相消之后

```
Σ(k=a..b) ΔIV[k] = IV[b] − IV[a−1]
```

**这是恒等式，不是近似**，所以前端聚合零信息损失，后端不必为每个可选周期各算一遍。

Skew 不能照搬：它是**水平量**（σ25P − σ25C，两点 IV 之差），把一组里的 skew 加起来
没有任何金融含义，只会得到一个随周期变化的假数字。取末值 = "这一格画的是该周期
**结束时**的读数"，与 K 线取收盘价同理。

**代价**：零穿越处会空一格（一组内符号翻转时只留末值）。留空比插一个假点诚实。

## 3. 量程为什么改成"下发窗口"而不是"下发极值"

原来的做法：后端算好 `skew_min`/`skew_max` 下发，前端直接用。改动的触发点是审查
前端排版时发现的两个问题：

1. 后端下发的极值是**整条序列**的极值。0DTE 尾盘只要有一个毛刺点就能把上界顶到
   几十个波动率点，色标/纵轴被拉满之后全天 0~1 的波动被压成一条平线。
2. 若改成让 ECharts 自动 scale，曲线会因为量程随数据跳动而"呼吸"，反而看不清真实
   的斜率变化。

两条都不可取，于是取中间：**按时间窗口取极值**。窗口开着一小时，早盘尖峰随时间
退出窗口，量程自动收回（实测上界 0.839 vs 关掉窗口的 10.620，差 12.7 倍）。

**窗口长度为什么由后端下发**：它是**业务口径**（"量程看最近多久"），不是呈现参数。
前端自己写一个默认值就等于把口径抄了一份，后端调整时两边会悄悄不一致 —— 这正是
本项目反复出现的"两份真相"。

**窗口按时间定义、与用户选的周期无关**：30 秒视图与 15 分视图看到的是同一段行情，
量程可比，切换周期时纵轴不会跳。

**基准时刻取最后一个"有时间戳"的列**，不是最后一个有 skew 值的列：断流恢复后末尾
可能挂着若干空列，拿空列当基准会把整个窗口往后挪。

**窗口内一个点都没有时回退到全序列极值**：可见数据整体短于窗口（刚开盘）或最近
一段断流而更早还有读数。若这时仍按空窗口给 ±0.18，画出来的曲线会整条跑到轴外被
裁掉。

## 4. 坑：`alignSkew` 的 `label` 是复制的，所以"标签一致"是恒真断言

`alignSkew` 里 `out.label = grid.labels.slice()` —— 标签直接从热力图网格复制。于是

```js
aligned.label[i] === view.labels[i]   // 永远为真
```

这条看起来最自然的断言**抓不到任何东西**。第一版验证就是栽在这里：五个周期全部
"逐列 label 完全一致 PASS"，而实际上聚合根本没发生（见下一条）。

**真正可失败的判据是时间域的**：每列的 `ts` 必须落在该列覆盖的**时间区间**内。
它只用 `ts` 与列网格，不碰 `bucket` 字段，因此与 `alignSkew` 的内部算法无关。

## 5. 坑：未解码的位图块喂给 `aggregate` 会**静默不聚合**

热力图数值块在线上是「位图 + 定标整数」，前端先 `decodeFrame` 还原成
`block.values` 再聚合。`aggregate` 的开头是

```js
if (!block || !block.values) { return block; }
```

于是把未解码的块直接喂进去，它**原样返回整块**：30 秒视图列数 780、列宽 30s，
聚合悄悄不发生，而所有对齐断言仍然通过（因为列网格与对齐用的是同一个错块，
自洽）。

**夹具因此必须走生产编码器**（`tools/skew_reference.py` 用
`HeatmapSerializer.encode`），不能图省事直接造一个带 `values` 的块。这条已写进
`skew_reference.py` 的模块 docstring。

## 6. 坑：被 `clipTail` 裁掉的历史段原本每帧刷一条告警

30 秒粒度下 780 列超过 `maxColumns=400`，从尾部截取后前面 380 列被裁掉。这 380 个
Skew 点落在 `col < 0`，原来的代码把它们算作 `stray` 并告警 ⇒ **每帧 380 条**
`[period] … 已丢弃`。

危害不是日志吵，而是**告警疲劳**：真正该响的那条（"帧里的 bucket 与热力图对不上"）
会被淹掉。现改为：`col < 0`（被裁剪的历史段，正常）静默；只有桶索引非法
（`b < 0`）或落在网格**右端之外**才告警。

## 7. 被否掉的方案

* **后端为每个周期各算一遍 Skew 序列** —— 传输层会变成"客户端相关"（要按前端
  当前选中的周期发不同数据），且换周期要等下一次推送。前端聚合是恒等变换，
  没有理由付这个代价。
* **把 `skew_min`/`skew_max` 与窗口极值都下发，前端二选一** —— 典型的两份真相
  加兼容分支。KAI 的工程要求明确禁止兼容分支堆叠，故直接**删除**旧键。
* **给前端加"列数必须等于分组后列数"的门禁** —— 违背 KAI 2026-09-13 的裁定
  「前端是空壳，后端报多少就渲染多少」。列网格的自适应属于**后端 L3** 的不变量，
  前端复制一份就是第二份真相。对齐这件事放在 `app.js` 的**接线**层（热力图先算、
  Skew 消费），而不是让 Skew 自己算一遍。
* **让 `check_web_contract.py` 的 import 挪进函数内**，使静态段能独立运行 ——
  改动小且合理，但属于"重构现有工具"，未获指令不擅自做。已记入 `OPEN-RISKS`。

## 8. 门槛教训：为什么需要 `check_web_syntax.py`

`web/skew.js` 因为 docstring 里多了一个 `*/` 而整个文件语法错误，
`window.SkewPanel` 不存在、Skew 面板整块空白 —— 而当时 13 个回归**全绿**。

不是断言写错了，是**根本没人在看这几个文件**：`check_period_aggregation.py` 只加载
`period.js`，`check_matrix_codec.py` 只加载 `matrix_codec.js`，
`check_web_contract.py` 只加载 `config.js`。`skew.js` / `heatmap.js` / `app.js` /
`ws_client.js` 一次都没被加载过。

教训：**回归的覆盖面要按"目录"清点，不能按"我记得测过什么"清点。** 只要有一个
前端文件不在任何检查器的加载清单里，它就是一个盲区。新门禁按目录枚举，
新增文件自动纳入。
