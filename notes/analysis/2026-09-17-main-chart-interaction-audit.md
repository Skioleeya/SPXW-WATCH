## 第一部分 · 主流金融前端主图交互逻辑

### 1.1 交互模式谱系（按用户意图分层）

| 意图层 | 交互模式 | 典型实现 | 反馈形式 |
|---|---|---|---|
| **视图导航** | 平移 pan | 网格内按住拖 / 中键拖 / 触屏单指拖 | 内容跟手移动 |
| | 缩放 zoom | 滚轮 / 轴区拖 / 两指 pinch / 框选 | 锚点处数值不动 |
| | 复位 reset | 双击 / 按钮 / 快捷键 / 右键菜单 | 视图回默认态 |
| | 自动跟随 auto-follow | 尾部追加列，窗口贴最新 | 需显式"已脱跟"指示 |
| **读数** | 十字光标 crosshair | 跟随指针的横竖线 | 轴标签气泡同步 |
| | 磁吸对齐 magnet / snap | 指针吸附最近数据点 | 光标跳格 |
| | 数据窗口 data window | 顶部读数条（OHLC / 指标） | 数值随指针变 |
| | 联动高亮 linked highlight | 多图同步十字光标 | 多图同位置同时亮 |
| **聚焦** | 刷选 brush / 区间选择 | 拖出矩形或区间 | 选区半透明 |
| | 联动筛选 cross-filter | 一图选择、他图过滤 | 他图变暗 / 重排 |
| **快捷** | 键盘 | 方向键平移、`+/-` 缩放、`Home` 复位 | 无 |
| | 右键菜单 | 上下文操作 | 菜单 |
| | 快捷键提示 | `?` 或悬停提示 | 浮层 |

### 1.2 设计原则

**① 直接操纵与"跟手"**
拖拽时**内容跟着指针走**，而不是"指针走、内容反向"。缩放时锚点固定 ——
指针按下处所指的数值 / 列在缩放前后保持不动。

**② 手势区域互斥，归属在按下那一刻冻结**
主流实现把"指针落在哪个语义区"在 `mousedown` **一次性定死**，整段拖动不再改判。
否则同一次拖动会一半在缩、一半在移（用户看到"图在抖"）。

**③ 容差与阈值（防误判）**
`lightweight-charts` 的实测常量（一手来源）：

| 常量 | 值 | 用途 |
|---|---|---|
| `CancelClickManhattanDistance` | 5px | 移动超过 5px 即不再算点击 |
| `DoubleClickManhattanDistance` | 5px | 双击容差（鼠标） |
| `DoubleTapManhattanDistance` | 30px | 双击容差（触摸，手指更粗） |
| `Delay.ResetClick` | 500ms | 点击计数复位 |
| `Delay.LongTap` | 240ms | 长按判定 |

**④ 状态可见（visibility of system status）**
任何"视图已偏离默认"都必须有**持久的视觉指示** —— 按钮高亮、徽标、`dataZoom` slider、
"自动跟随"开关的 on/off、窗口边框 —— 而不是只在操作发生的那一瞬有反馈。
判据：用户离开 30 秒回来，能否一眼看出图还是不是自己调过的样子。

**⑤ 可逆性（reversibility）**
视图改变必须有一条**低成本的显式复位路径**（按钮 / 快捷键 / 双击），
且**同一个手势在所有主图上语义一致**。

**⑥ 可发现性（discoverability）**
- 悬停时**游标语义变化**：`grab` / `grabbing` / `ew-resize` / `ns-resize` / `crosshair`
- 悬停时**元素自身有响应**（`emphasis`：描边、提亮、放大）
- 提示文案描述**当前状态**，而不是**操作说明书**

**⑦ 输入设备无关（device independence）**
`lightweight-charts` 的 `MouseEventHandler` 把 `MouseEvent` 与 `TouchEvent`
归一化成统一的 `localX/localY`，并为触摸单独实现：两指 pinch 缩放、240ms 长按、
`preventDefault + passive:false` 阻止页面滚动、以及"纵向优先"的方向偏置
（避免抢走页面滚动）。

**⑧ 实时图的特殊约束：视图状态必须独立于数据流**
实时主图每帧追加数据。若视图状态（窗口、量程）由数据流持有，
数据一到就会把用户的视图冲掉。主流做法是把视图状态提出来做**单一真源**，
每帧重新"贴"到图表上。

### 1.3 关键实现方式（可直接对照的清单）

1. **事件归一化层**：mouse / touch → 统一坐标 + 统一语义
2. **手势状态机**：`mousedown`（定归属、取基准快照）→ `mousemove`（相对基准算增量）
   → `mouseup` / `globalout`（收尾，并补一次"节流窗口内没落地的最后一次移动"）
3. **基准快照，而非增量累加**：整段拖动都相对按下时的基准算 ——
   逐次累加会让浮点误差一路攒起来，指针拖回原位也回不到原状态
4. **自愈**：`mousemove` 时若发现左键已不在按下状态，立即清拖动态 ——
   少了这条，一次漏掉的 `mouseup` 会让图此后一直跟着指针乱动
5. **视图状态单一出口**：面板持有状态，图表只被"贴" ——
   避免"屏上已缩、下一帧又被自动量程冲掉"
6. **双坐标换算**：像素 ↔ 数据值，缩放锚点靠它
7. **节流 / rAF 合帧**：拖动中每像素重绘会占满主线程，拖累同页其它面板
8. **容差比较**：浮点量程用 epsilon 比较，否则"其实没变"被判成"变了"
9. **越界归一化**：全宽窗口一律归一化成 `null`，一种状态只有一种写法
10. **触摸专项**：pinch、长按、阻止页面滚动、方向偏置

### 1.4 来源

- **一手**：TradingView `lightweight-charts` — *Crosshair and User Interaction*
  （`src/gui/mouse-event-handler.ts`、`src/model/crosshair.ts`、`src/model/magnet.ts`）：
  `CrosshairMode` = `Normal / Magnet / Hidden / MagnetOHLC`；事件归一化与 §1.2③ 的常量表；
  触摸的 pinch / 长按 / 滚动阻止 / 方向偏置。
- **归纳**：其余模式（轴区拖拽缩放、复位路径、状态徽标、联动刷选等）
  为对主流交易终端与数据可视化惯例的归纳，**未逐条取一手来源** —— 按本仓惯例标注为归纳。

### 2.1 逐维度缺陷

#### 维度 A · 交互流程（interaction flow）

**A1 【最高】热力图纵向没有交互流程**
用户对热力图的核心问题是"**哪些行权价的 IV 在动**"。当前档位窗口由现价自动跟随
（容差 8 档），用户**无法手动上 / 下查看其他行权价**。
- 操作路径被迫变成"等现价动"：想回看上方 Call 的冲量，只能等。
- 这是**功能缺口**，不是手感问题。

**A2 【高】"全宽时横向拖不动"是静默无操作**
`heatmap.js::_panMove` / `skew_zoom.js::_pan` 在"无窗口"时整段跳过。
设计意图正确（全宽 = 自动跟随，凭空长窗会让它静默脱跟），但屏幕上**没有任何指示**。
- 症状：用户拖了、图不动 → 归因为"坏了"。**静默无操作比报错更难查。**

**A3 【中】双击语义在两图不一致**
热力图双击 = 只复位横轴；Skew 双击 = 复位三条轴。
同一个手势、两个面板、两种含义 → 破坏"手势语义全局一致"这条基本原则。

#### 维度 B · 状态反馈（state feedback）

**B1 【高】"已缩放 / 已锁定 / 已脱跟"只有文本，没有图形指示**
- 热力图：横轴窗口只体现在 meta 行 `横轴 a–b/N 列`
- Skew：纵轴锁定只体现在 meta 行 `纵轴锁 25ΔSkew[…] / IV[…]`

没有"已缩放"徽标、没有窗口边框、没有 `dataZoom` slider、没有"自动跟随"开关的 on/off 态。
- 后果：用户离开 30 秒回来，**无法一眼判断**图还是不是自己调过的样子。

**B2 【高】Skew 两条 Y 轴独立锁定 ⇒ 静默误读风险**
轴区拖动只锁一侧。此后左右两条轴的**同一屏幕高度代表不同含义**，
而图上**没有任何视觉提示** —— 两条轴的刻度颜色、字重、字号完全相同。
唯一提示是 meta 行的文字。
- 后果：用户可能把"左轴放大、右轴没放大"的图当成正常双轴图读数。
- 注：这是 KAI 2026-09-17 的明确裁定（"拖哪侧只缩哪侧"），
  本条**不是**说该裁定错，而是说裁定之后**缺少配套的视觉提示**。

**B3 【中】数据未到 / 无数据时 Skew 面板是纯空白**
`app_render.js::renderSkew` 在 `!block || !block.series` 时直接 `return`，
面板既不显示"等待数据"，也不显示"该时段无数据"。
对比热力图有 `该时段尚未开始` 的文案（`app_render.js:94`）。
- 后果：用户无法区分"还没数据"与"页面坏了"。

**B4 【低】拖动过程中无"正在拖"的视觉态** —— 无 `grabbing` 游标、无元素高亮。

#### 维度 C · 操作路径（operation path）

**C1 【高】复位路径单一且不可发现**
唯一复位 = **双击**，且只在 10.5px、低对比度（`--text-faint`）的 hint 文本里提过。
没有复位按钮、没有快捷键、没有右键菜单。
- 后果：用户误操作后，要么恰好记得双击，要么刷新页面。

**C2 【高】手势归属靠"读说明书 + 试错"**
Skew 实际有**四个**手势区（左轴区 / 网格 / 右轴区 / 底部轴区），边界**完全不可见**。
用户必须先把 hint 读一遍，才知道哪里能拖、拖了会怎样。

**C3 【中】两图不联动 ⇒ 跨图对时靠肉眼**
2026-09-17 KAI 主动取消两图联动（`app.js:78-85` 有记录）。代价是：
要比较"热力图上某段冲量"与"Skew 上同一段时间"，必须在两张图各调一次窗口。
- 这是**明确的取舍**，不是缺陷 —— 但"取消联动"之后**没有替代手段**
  （如两图同步的十字光标、或共享的时间游标），代价被全额保留。

**C4 【中】无键盘路径**
全项目无 `keydown`。方向键平移、`+/-` 缩放、`Esc` / `Home` 复位这类零成本路径缺失。
- 对"盯盘"场景（一只手在别处 / 需要精确复现某个视图）尤其明显。

#### 维度 D · 视觉引导（visual affordance）

**D1 【高】游标语义缺失**
`style.css` 里 `cursor` 只出现在两个按钮组（`.sessions button` / `.periods button`）。
图表网格、Y 轴区、X 轴区**全都没有** `grab` / `grabbing` / `ns-resize` / `ew-resize` / `crosshair`。
- 后果：可交互区域对用户**完全不可见** —— 这是可发现性的第一道线索，却完全没用上。

**D2 【高】热力图悬停无元素级反馈**
`heatmap_option.js` 没有 `emphasis`，只有 tooltip。指针移到一个格子上，
格子本身**没有任何变化**（无描边、无提亮）。
- 后果：用户无法确认"我指的是不是这一格"，色块密集时尤其明显。

**D3 【中】热力图无十字光标（`axisPointer`）**
`trigger: "item"` ⇒ 必须**精确悬停在单元格**上才有读数。
无法"沿一条时间列纵向扫"，也就无法用交互回答"这一桶里哪些行权价动得最猛"
（当前只能看 foot 行的 Top5，且不可交互）。
对比：Skew 有 `axisPointer{type:"line"}`（竖线）。

**D4 【中】提示文案是"操作说明书"而非"状态"**
hint 写的是"按住左键拖动：…"（10.5px、`--text-faint`）。
用户每次都要重新读一遍才能确认当前图处于什么模式；
而状态类信息（当前窗口、是否脱跟、哪条轴被锁）在另一处（meta 行）。
- 两类信息**位置分离**，用户需要来回对照。

**D5 【低】色标不可调** —— `visualMap.calculable: false`，
无法缩小色标范围以看清小幅波动。

#### 维度 E · 输入设备覆盖

**E1 【中】触摸 / 触控板多指手势未接**
全项目无 `touchstart` / `touchmove`。主流实现为触摸单独做了 pinch 缩放、长按、
`passive:false` 阻止页面滚动、纵向优先的方向偏置。
- 现状：触屏设备上手势**未实现、也未验证**（`notes/context/open_tasks.md` 已记"触屏未接"）。

**E2 【低】无 pinch / 无长按 / 无右键菜单。**

#### 维度 F · 一致性与可预测性

**F1 【中】"全宽 = 自动跟随"这条约定在两图上已收敛，但没有视觉化**
两图的 `_xWin === null` 都表示全宽 / 跟随最新 —— 这是好的收敛（同一手势同一语义）。
但"当前是否在跟随"没有任何图形指示。

**F2 【低 · 技术债】热力图横轴缩放由 ECharts 自带、平移由面板自实现**
两条路径都写同一个 `_xWin`，目前口径一致（都按 `/(cols-1)` 换算），
但"一个状态两个写入者"是长期风险。

### 2.2 优先级建议（按"用户损失 ÷ 修复成本"）

| 优先级 | 项 | 为什么是这个优先级 |
|---|---|---|
| **P0** | A2 静默无操作反馈 · B1 状态无图形指示 · D1 游标语义 | 几乎零成本（CSS + 一个小徽标），直接消除"图坏了"的误判 |
| **P0** | D2 悬停高亮 | 一个 `emphasis` 配置项 |
| **P1** | A1 热力图纵轴可交互 | 需要新增一条交互通道（成本中等），但补上**最大的功能缺口** |
| **P1** | C1 复位按钮 · C4 键盘映射 | 复位按钮几行 HTML + JS；键盘映射表很轻 |
| **P1** | B2 双轴独立锁定的视觉提示 | 两条轴刻度用不同颜色 / 字重，或加锁图标 |
| **P2** | B3 空状态文案 · D3 十字光标 · D4 文案分层 | 改善明显，成本中等 |
| **P2** | E1 触摸 | 需要接 pinch / 长按，且必须真机验证 |
| **P3** | D5 色标可调 · F2 写入者收敛 | 收益 / 风险比低 |

### 3.1 本轮确立的通用不变量（重要）

> **凡必须在帧间持续存在的反馈，都不能建在 ECharts 内部状态上。**
> 两个面板每 ≤400ms 一次 `setOption(opt, true)`（`notMerge`），实测会摧毁：
> - 悬停/emphasis —— 指针静止不动，**+450ms 后消失**；
> - 原生 `axisPointer`（cross / root / axis 三种挂法 + 5 种变体全试）—— **一次都没画出来**；
> - ECharts 自带 `moveOnMouseMove` 拖拽 —— 8 段拖拽只有**前 3 段**生效。

因此第 7 项（以及第 2 / 4 / 6 项的常驻可见部分）一律做成 **DOM 覆盖层**
（`web/heatmap_hover.js` / `web/skew_regions.js` / `web/view_chips.js`）：
与重建无关，也不吃 `setOption` 的 p50 = 27ms 预算。
每帧重建后再用 `dispatchAction({type:"showTip", x, y})` 按**像素**补一次提示框
（不能用 `dataIndex` —— 列每帧在追加，索引会漂）。

另两条踩到的坑，已写进 skill：
- `zr.handler.findHover(x, y, null)` 返回的是**对象 `{target, topTarget}`，不是数组**；
- 热力图**左侧约 2/3 是空的**（还没有数据桶），在那里取样必然"什么都查不到"
  —— 必须先看一眼截图确认取样点有数据，再相信否定结论。
