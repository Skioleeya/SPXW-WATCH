# Project State — notes-dedup-tiering

本文件只写**取舍理由**。改了什么在 `handoff.md`，命令证据也在 `handoff.md`。

## 1. 为什么砍 `meta.yaml` 而不是砍 `project_state.md`

候选是二选一，不是全砍。两边各有一个独有载荷：

| 候选 | 独有载荷 | 是否可替代 |
|---|---|---|
| `meta.yaml` | `status` / `deliverables` / `validation_commands` 的机器可读索引 | **可替代** —— 前两者折进 `handoff.md` 的 key header 与 `CHANGED-PATHS`，第三者本就在 `COMMAND-EVIDENCE` |
| `project_state.md` | 设计取舍理由、被否掉的方案、踩到的坑 | **不可替代** —— `handoff.md` 的 `## 结论` 只记"做了什么"，不记"为什么不是另一种做法" |

决定性证据：**仓库内 `meta.yaml` 的消费者为零**（`grep` 零命中）。
一个没有任何读者、且三项内容全是别处镜像的文件，是纯仪式。

反过来说，`project_state.md` 里那句"为什么不留 `--live`"这类判断，
恰恰是下一个会话最需要、而任何机械清单都装不下的东西。

## 2. 为什么 session 级 `open_tasks.md` 该删

它的三段内容各有归宿，没有一段是它独有的：

- `## Active` → `notes/context/open_tasks.md` 才是活清单的**唯一真相**（skill 原文即如此）。
- `## Stale / Needs Verification` → 同上。
- `## Closed（本会话）` → 折成 `handoff.md` 的 `## Closed in session`。

保留它等于把同一份待办列表在同一仓库里维护两遍 —— 这正是"数字腐烂"的经典形态：
改了 `context/` 忘了改 session 级，两边就永久分叉。

## 3. 备选方案 B（已裁定不采用）

> **KAI 2026-09-13 裁定：不采用 B，保持 A。** 本节理由保留备查，**不再作为待议项重提**。

**B = `startup.md` + `handoff.md` + `meta.yaml`**，即保机器索引、舍设计理由。

不采纳的理由：本仓库（乃至目前所有项目）没有任何脚本读 `meta.yaml`，
而设计理由每一轮都在被引用（`notes/context/project_state.md` 的"仍然有效"节
本质就是历次设计理由的汇总）。

**若将来出现跨会话的机器消费需求**（例如按 `status` 批量列出会话、CI 校验记录完整性），
B 会立刻变得更优 —— 那时应该**恢复 `meta.yaml` 并写一个真正的消费者**，
而不是让一个无人读的文件长期存在。这条判断留给将来，不预先建空壳。

## 4. 为什么不回溯历史 8 个会话

> **KAI 2026-09-13 裁定：不回溯。** 该裁定已提升为 skill 通用规则
> （"Changing this shape is forward-only"）—— 它不再是"本项目的一个选择"，
> 而是规则本身，因此下个会话不会重新提出。本节理由保留备查。

三层理由，从强到弱：

1. **它们是证据，不是草稿。** 会话记录的价值在于"当时确实这么做了"。
   事后改写会破坏这一属性 —— 这与 skill 禁止回填 `startup.md` 是同一条原则。
2. **改写会制造第三种真相。** 8 个会话的 `meta.yaml` 与 `open_tasks.md` 若被删，
   而 `notes_backup_20260911/` 里那份副本仍在（35 文件逐字节相同），
   备份就成了"旧格式的唯一留存" —— 删除反而制造了新的分叉。
3. **收益为零。** 新规则只约束后续写入；历史格式不影响新会话的可读性。

## 5. 踩到的坑

- **分级表引入当天就被自己撞上。** 本会话前半段是只读审计（按定义属 T1），
  删减决策落地后变成 T2。**就地升级**是正确解，**回填 `startup.md` 不是** ——
  这也是 `STARTUP-PROOF` 只能写 `N/A:<reason>` 的原因。
- **"文件数下降"与"行数下降"不是一回事。** skill 从 137 涨到 186 行，
  但每会话文件数上限从 5 降到 3。若只盯行数会误判为"越改越重"。
  真正该盯的指标是**同一事实的写入次数**。
- **否定句会被自己的 grep 抓到。** 复核"是否残留旧五件套引用"时，
  `no meta.yaml` / `this replaces meta.yaml` 这类句子会命中 ——
  必须逐条判读，不能只看计数。
